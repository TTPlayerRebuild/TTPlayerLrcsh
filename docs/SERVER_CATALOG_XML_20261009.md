# 歌词服务器 XML 优先及 INI 兼容

日期：2026-10-09；本地候选：`2026.10.09p3`。

本文为 p3 历史记录。p4 已解除 XML 模式的两项限制，支持 1～128 个服务器；XML 优先、不自动刷新及 INI 迁移规则不变。见 [多服务器实现](MULTI_SERVER_ORIGINAL_HOST_20261009.md)。

## 确认后的规则

文件均位于插件旁，扩展名由 DLL 文件名替换得到。默认是 `AddIn/ttp_lrcsh.xml` 和 `AddIn/ttp_lrcsh.ini`；两者内容格式都为 UTF-8 XML。

| 宿主及文件状态 | 读取 | 保存与刷新 |
|---|---|---|
| 重建播放器，已有 XML | XML | 编辑器只保存 XML；不从 INI 或服务器列表自动覆盖 |
| 重建播放器，无 XML、有 INI | 将 INI 完整复制为 XML，再读取 XML | 保留原 INI，后续编辑只写 XML |
| 重建播放器，两者均无 | DLL 内置服务器 | 首次保存自定义服务器时创建 XML |
| 原版 EXE＋重建 DLL，已有 XML | XML 中前两个服务器槽 | 保持 XML，不执行 `?svrlst`；不写 XML 或 INI |
| 原版 EXE＋重建 DLL，无 XML | INI；不存在时使用资源默认值 | 延续此前的 INI 刷新与保存路径，DLL 不自行迁移 XML |
| 原版 EXE＋未经替换的原版 DLL | 仅 INI | 原 DLL 不支持 XML 优先，必须替换为本重建 DLL |

“保持 XML”针对服务器目录，不影响正常的歌词搜索及下载请求。原版宿主仍只获得两个插件工厂；第三个及以后的服务器条目不会被截断写回，可以留给重建播放器使用。重建版继续在内置只读条目后显示 XML 自定义条目，保留原来的编辑、排序规则。

存在 XML 就选择 XML，即使文件为空、损坏、不可读，或同名路径为目录，也不会静默改用 INI、重新启用远程目录刷新或覆盖该路径。原版旧接口会返回无效服务错误；重建版编辑器显示读取失败并保护文件。修复文件后，重启原版播放器；DLL 在模块生命周期内缓存服务器目录，不监视文件实时变化。

## 原版伪代码依据

依据本地 `rebuild/tests/lyrics/ncab/pseudo/ttp_lrcsh.dll.pseudo.c`：

- `60351249`：取得模块路径并替换扩展名，读取同名 INI，调用 `60351BE8` 的非保存模式；读取失败后使用资源中的两个默认服务器。
- `60351420`：用临界区保护“只刷新一次”状态；首次搜索进入目录请求路径，非空响应交给 `60351BE8`，空响应走 `DeleteFileA`。
- `60351BE8`：最多解析两个服务器槽；保存时去除目录中的 `query_url` 和首个推广链接节点，并写入收到的目录，不与磁盘原文件合并。
- `6035716F`：原版保存使用覆盖创建及写入，因此原 INI 可能被远程目录替换。
- `60354D1D`：仅枚举工厂 0、1；第三个返回无效参数。两个入口的限制来自 DLL。

原播放器在 `004C88D9` 附近解析插件导出并枚举工厂，枚举直到插件返回失败。原 DLL 的目录解析循环明确要求 `iVar7 < 2`；工厂枚举明确拒绝 `param_2 > 1`，返回 `0x80070057`（`E_INVALIDARG`）。因此若后续要让原播放器显示更多服务器，需要扩展重建 DLL 的目录存储、工厂枚举及索引访问，再验证原版宿主，而非只修改 XML 文件。

因此只把 INI 改名为 XML 不够：必须同时在 XML 模式下停止目录刷新。本次通过 `Catalog::Catalog` 标记 XML 目录无需刷新，令 `Catalog::Refresh` 直接返回。无 XML 的路径保留此前已修正的原子写入、失败保留配置、HTTPS 防降级等行为；并未重新引入原版空响应删除文件的缺陷。

## 实现与迁移保护

### 插件

`src/catalog.cpp` 先检查 XML 是否存在。只有明确的文件或路径不存在错误才选择 INI；其余错误不会启用 INI 回退。保存函数仍明确以 INI 为目标，XML 模式不进入该函数。XML 和 INI 共用既有解析器及本地 `ca_file` 支持。

### 重建播放器

`src/lyrics/service_catalog.cpp` 改为使用 `ServiceXmlPath`：

1. 在目标目录创建临时文件，完整复制 INI；不先解析重写，保留 BOM、换行、注释、未知属性及全部服务器条目。
2. 将完整副本重命名为 XML，不允许覆盖并发创建的 XML。
3. 复制失败时清理临时文件，保留 INI；不遗留半份 XML。下次读取可以重试。
4. 编辑保存仍使用原来的冲突检测、临时写入和替换备份，备份文件改为 `ttp_lrcsh.xml.bak`。
5. 已保存的服务器标识仍保留旧 `ini|` 前缀，避免升级后丢失当前服务器选择；该标识不决定文件路径。

迁移只是复制，不删除 INI。XML 存在后，对 INI 的后续更改不会自动同步到 XML。用户需要恢复原版 INI 刷新行为时，可在关闭播放器后自行移走 XML。
