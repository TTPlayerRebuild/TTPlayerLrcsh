# 原版播放器的多歌词服务器支持

日期：2026-10-09；本地版本：`2026.10.09p4`。

## 结果与使用

使用本次重建的 `AddIn/ttp_lrcsh.dll`，原版播放器可以显示并使用 `ttp_lrcsh.xml` 中超过两个的服务器。无需修改原版 `TTPlayer.exe` 或替换原版 `ttpcomm.dll`。

关闭播放器，将插件更新到 p4，并将服务器列表放在同目录的 `ttp_lrcsh.xml`。其格式仍为原来的 UTF-8 `ttp_lrcsvr` 文档，例如：

```xml
<ttp_lrcsvr>
  <server name="服务一" url="http://127.0.0.1:99/one"/>
  <server name="服务二" url="http://127.0.0.1:99/two"/>
  <server name="服务三" url="http://127.0.0.1:99/three"/>
</ttp_lrcsvr>
```

以上地址仅用于展示格式，需要换成实际提供千千歌词协议的服务器。HTTPS 仍须配套 ABI 6 `ttp_https.dll`。

| 配置 | 本次行为 |
|---|---|
| 存在有效 XML | 按实际顺序枚举 1～128 项，不自动请求 `?svrlst`，不改写文件 |
| 无 XML，存在 INI | 保留原版两项及此前的刷新、原子保存 INI 路径 |
| 两者均不存在 | 原版两个资源默认服务器 |
| XML 为空、损坏、无服务器或超过 128 项 | 不回退 INI、不覆盖 XML；保留两个报错入口，使重建宿主仍能发现插件并打开配置编辑器 |
| XML 中个别服务器名称或 URL 无效 | 保留该位置作为无效入口，搜索报错；后续条目索引不前移，不串用其它服务器 |

128 与重建播放器编辑器的上限一致。超过上限会拒绝整份 XML，不静默截断前 128 项。只有一个有效条目的 XML 只枚举一个工厂，不再附加空白第二项。

原版播放器将选择保存为数字 `AddInIndex`。列表不变时退出重启会恢复原选项；如果手动重排或删除 XML 条目，同一数字可能指向不同服务器，需要重新选择。配置在 DLL 生命周期内缓存，修改数量、顺序后必须重启播放器；本次没有增加热重载。

## 原版证据

- 原 DLL `60351BE8` 的目录解析循环限定 `iVar7 < 2`；`60354D1D` 的工厂枚举拒绝大于 1 的索引，返回 `0x80070057`。
- 原播放器 `004CABC0` 从 0 开始调用模块枚举，每次成功后递增，直到 HRESULT 失败。歌词工厂 GUID 为 `9D5AE963-7DF6-4323-B4CF-FBDA159BFF15`，没有只运行两次的判断。
- 原播放器 `004CDC47` 将歌词工厂加入可扩容数组；每项 0x14 字节，容量不足时扩容。
- 设置序列化函数读取、写入 `Lyric` 的 `AddInIndex`，没有把它限制在 0、1。GUI 实测进一步确认索引 7 能保存并恢复。

因此限制属于原 DLL，不需要改变原宿主 ABI。

## 实现

1. `src/catalog.cpp` 区分本地 XML 的扩展解析与 INI／远端目录的旧解析。前者最多 128 项，后者保持两项。
2. `src/core.h` 增加 `Catalog::Count()`。数量在构造时确定；INI 刷新只更新槽位，不改变数组长度，已有工厂索引保持有效。
3. `src/plugin.cpp` 的 `Enumerate` 按实际数量检查索引，越界仍返回 `E_INVALIDARG`。导出、GUID、vtable 布局、引用计数、名称分配及搜索下载接口不变。
4. 重建播放器 `src/lyrics/service_catalog.cpp` 修正只暴露一个工厂时的默认项索引：同一模块的两个资源默认项都可通过其第一个工厂配置，不能让第二项错误指向下一模块。

## 实测范围

### 原版 GUI，Windows 11

隔离副本使用原版 5.7 EXE 和原版 ttpcomm，逐字节核对与工作区原文件一致，仅替换歌词 DLL。测试服务只在本机提供静音音频及固定歌词。

- 在线搜索下拉框实际显示 XML Server 1～8。
- 第三项搜索、下载成功，保存歌词含 `Lyrics from server 3`。
- 第八项搜索成功，第二条候选下载并保存，正文含 `Lyrics from server 8`。
- 原版窗口歌词显示第八项正文。
- 正常关闭主窗口后，测试 EXE 的同名配置 `ttplayermulti.xml` 保存 `AddInIndex="7"`。
- 重启同一副本后自动从第八项搜索，下载并保存第八项第一条候选。网络日志和歌词文件均作核对。

### 自动回归

- 本机多服务器 20 次旧接口运行：1、2、3、8、128 项；超限 129 项；中间无效项；重复名称；INI 八项仍只枚举两项。核对每项实际请求路径及下载结果，XML 原文保持不变。
- XP、Win7 各 7 次旧接口运行：一项、第三项、第八项、回到第一项、第 128 项、INI 两项兼容、损坏 XML，全部通过。本轮使用 ABI 探针，没有重跑虚拟机 GUI 全流程。
- 本机原有 XML/INI 优先级 8 组与原协议 22 场景通过。
- 重建宿主 `lyric_service_catalog_tests`、`lyric_search_tests` 通过；增加两份 DLL 分别使用一项和三项 XML 的实际加载测试，验证工厂数量、配置不重复及默认项索引所属模块。
- 8 项插件包／下载验证及播放器包全部文件摘要核对通过。插件 XP/Win7 导入检查为 5 个系统 DLL、94 个导入；播放器为 20 个 DLL、717 个导入。

Win10 按此前约定由 Win11 代验，没有原生 Win10 实测。所有测试源码和日志位于 `rebuild/tests`，不提交插件仓库、不加入发行包、Actions 不运行这些测试。
