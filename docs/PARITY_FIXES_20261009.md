# ttp_lrcsh 兼容修复与 XP 复测

日期：2026-10-09；本地候选版本：`2026.10.09p1`。

本次根据 [初次差异审计](ORIGINAL_PARITY_AUDIT_20261009.md) 的顺序修复生产 DLL，并在恢复的 XP、Win7 和本机 Windows 11 验证。Windows 11 按用户要求代替 Windows 10 测试，不能写成原生 Win10 实测。

## 1. 原版契约与修复

| 项目 | 原版依据 | 本次修改 |
|---|---|---|

| XML 签名数据 | `60355612` 只替换五种命名实体 | 保留数字及未知实体原文；重复属性取首次值，保留数量上限。修复名称看似相同但下载签名不同的问题 |
| 空歌手 | `60352282` 只要求 title 非空指针 | artist=nullptr 等同空字符串；title=nullptr 仍 E_POINTER |
| 忙碌命令 | `60352443` 替换旧命令并取消旧请求 | 新搜索／下载可覆盖待处理命令；递增操作代数，丢弃过期结果和错误，防止覆盖新操作 |
| 初始化握手 | `603520CD` 等待最多 5 秒，`60353322` 先初始化 WinINet | worker 报告真实就绪结果；QI、CreateThread、InternetOpen 失败后回滚并允许重试；异常退出后不再接受无人处理的任务 |
| 宿主回调与释放 | 原宿主 `0043B332`→`0043BAA3` 含同步 UI 消息；`0043BB8D`→`004045F3` 释放 Search | 状态锁内决定回调准入，锁外调用宿主。最终 Release 等待在途回调时处理同步发送消息，解除 UI 与工作线程互相等待；回调中最终 Release 不等待自己 |

核心生命周期代码移到 `src/search.cpp`；`src/plugin.cpp` 保留工厂和导出。

## 2. XP 实测发现的额外问题

XP 的 `InternetCrackUrlW` 在没有用户名、密码、路径等字段时，可能让相应长度保留输入的 `DWORD(-1)`，同时返回空指针。旧判断仅检查用户名／密码长度，导致普通 HTTP 地址被误判为包含凭据，Configure 返回 E_INVALIDARG；仅做导入表检查发现不了这个问题。

现改为同时检查返回指针和长度，host/path/extraInfo 的读取也使用同样边界。修复后 XP 可配置服务、搜索两条候选并按 0→1→0 连续下载；包含溢出 ID 和数字实体，Cookie 会话均保留。

## 4. 仍保留的差异与未覆盖范围

1. 不调用 TerminateThread，不发送 `ci` 机器标识，刷新失败不删除可用 INI；继续保留 UTF-8、响应大小、候选数、XML 深度和 HTTPS 降级限制。
2. Cancel 的边界是“回调准入”：取消前已获准进入的回调仍可完成。最终 Release 排空在途回调后至多等网络线程 1 秒；如果宿主回调永久阻塞，仍不能保证有限时间退出。只泵送同步发送消息，避免处理排队 WM_CLOSE 导致窗口销毁重入。
3. 65 秒是跨请求跳转的检查期限；单次系统阻塞调用可能晚于期限返回。未完成长时间断网／系统代理 PAC／SOCKS／所有代理认证方式的矩阵。
4. HTTP 206 完整范围检查目前在原生 WinINet 分支；HTTPS ABI 5 没有暴露 Content-Range，不能声称两个传输分支已完全相同。
5. VM 的 HTTPS 验证是配套组件 ABI 5 的真实加密请求；未完成歌词 DLL 连接真实现代 HTTPS 歌词服务的端到端验证。原版 GUI 的全部快速换歌／关闭竞争仍需更长时间的专项压力测试。
6. 临时目录保存仍受 GetTempFileNameW 的 MAX_PATH 限制；超长目录未覆盖。XML 保留策略只承诺指定节点／属性语义，不承诺与旧 XML 库的空白排版逐字节相同。
7. 远端正式发行和 Action 运行未执行；本次仅生成本地候选包。历史审计中的远端 404 是当时观察，本次未重查。
