# 原版播放器 HTTPS 歌词修复与验证

日期：2026-10-09。歌词插件 `2026.10.09p2`，配套 HTTPS 组件 `2026.10.09`。

## 1. 结论和“原版”的含义

本次的原版是 **原版 TTPlayer.exe 播放器**，不是只要求与旧歌词 DLL 的函数返回值一致。

原版 EXE 和原版 ttpcomm.dll 无需更改；用重建 `ttp_lrcsh.dll` 替换歌词插件，并在同一 AddIn 放入支持 ABI 6 的 x86 `ttp_https.dll`，可通过原版界面完成 HTTPS 歌词目录、搜索、下载、保存和显示。

已在 XP、Win7、本机 Windows 11 使用原版播放器的隔离副本完成正常 HTTPS 流程。Windows 11 按用户要求代验 Windows 10，**未称为原生 Win10 实测**。这项扩展仅覆盖歌词插件的请求，不能自动给原播放器的音频流、更新器或其它插件增加 HTTPS，也不能恢复已停服的服务器。

## 2. 原版依据与本次修正

原版伪代码路径及反汇编证据见 [修复前续审](HTTPS_ORIGINAL_HOST_AUDIT_20261009.md)。关键关系：

- 原播放器 `004C88D9 / CSoundAddInModule_CreateInstance` 加载工厂，通过旧 Search 接口交互。网络请求在插件内部，因此可在保持工厂、GUID、虚表、回调和内存所有权的前提下升级传输。
- 旧歌词 DLL 的 `60351420` 仅允许 HTTP 目录刷新；`60351585` 请求未为直接 HTTPS URL 加入 SECURE 标志。新插件自行使用 TLS，不依赖原 EXE 知道新增接口。
- 原版 GUI `0043B332 → 0043BAA3` 及关闭路径 `0043BB8D → 004045F3` 的同步消息约束仍由已修复的生命周期实现处理。

| 修复 | 当前实现 |
|---|---|
| HTTPS 缺少范围信息 | ABI 6 返回 Content-Range，HTTP／HTTPS 统一检查；存在范围头时必须覆盖完整正文，拒绝部分、通配、溢出或格式错误范围。无范围头的 206 继续保持既有兼容策略 |
| 204／304 等待连接关闭 | 按无正文响应结束；204 的空搜索仍报无效响应，304 仍按状态报错，不当作成功歌词 |
| 跳转被 gzip／超大说明正文阻断 | 歌词请求选用只读成功正文策略；状态、Location 和 Set-Cookie 仍可用。成功正文仍受大小和编码限制 |
| HTTPS 请求头与原版不同 | 恢复原 MSIE 6.0 UA、Accept 列表和 scheme://host/ Referer；仍请求 identity 编码并关闭单次连接 |
| 目录可将 HTTPS 改回 HTTP | 按两个工厂槽逐项检查，拒绝降级；有效槽仍可更新，无效槽保留旧配置 |
| 多个 extra 取值不同 | 初始 INI 和刷新统一取首个 extra；仍清除所有持久化 extra，保留有意修正 |
| helper 错误不清楚 | 缺失／旧 ABI、证书失败、TLS 失败、无效私有 CA、代理回退冲突分别通过旧 OnError 回调说明 |
| 每次请求重复加载 helper | 按 Search 生命周期缓存，先释放响应再卸载，不改变旧宿主 ABI |
| 分发只校验文件摘要 | helper 增加 PE 能力资源，播放器下载脚本静态确认 ABI 6，再检查 XP／Win7 导入，不执行制品 |

## 3. 私有服务配置

普通公共证书服务无需 ca_file。自建服务可明确配置本地 CA：

```xml
<ttp_lrcsvr>
  <server name="我的 HTTPS 歌词服务"
          url="https://lyrics.example.invalid/lyrics"
          ca_file="my-server-ca.pem"/>
</ttp_lrcsvr>
```

上例为不可连接的示意地址；必须换成实际提供千千旧歌词协议的服务。PEM 放在 AddIn，与歌词 DLL 同目录。文件名仅允许本地名称，拒绝目录、UNC、ADS 等路径表达，限制大小、NUL 和无 PEM 标记输入。

CA 只作用于显式配置的协议、主机、端口。跨源跳转不携带私有信任，目录跨源更新不继承私有信任；远端 ca_file 属性被剥除，不能增加本机信任。相同源的目录更新保留本地 CA 配置。不会写系统证书库或关闭校验。

缺失／不兼容 helper 不再默默退到旧系统 TLS。helper 仅在无法处理的系统代理场景显式要求原生回退；存在私有 CA 时拒绝该回退。证书／TLS 错误不回退。

测试使用回环／VirtualBox NAT 的受控 TLS 1.3 歌词服务及本地显式 CA；不是公网服务可用性证明。测试曲目为静音 WAV，独立配置、播放列表和歌词文件。

|---|---|

**发布顺序：先发布支持 ABI 6 的 ttp_https，再发布歌词插件／运行播放器 Action。** 播放器 Action 仍选择最新稳定版本；若线上最新 helper 未支持 ABI 6，静态校验将明确失败，而不是打入不可用的组件。本次未提交、推送、发布或触发远端 Action。

## 7. 仍有边界

- 旧协议、两个工厂和原版回调已保留；不声称二进制完全复刻或所有异常输入完全等同。
- Cookie 按 Search、同源及路径隔离；不会恢复旧 WinINet 的全局 Cookie 存储。
- TLS 成功正文不支持服务端违背 identity 请求而返回 gzip；Connection 仍为 close，没有 TLS 连接复用。
- 证书／范围等异常已通过探针验证，未在三系统原版 GUI 中逐一重复所有异常对话框。正常退出、同步回调回归不能证明所有快速换歌／关闭竞态。
- 系统代理、PAC、SOCKS 和全部认证方式、长期断网、区域设置和长路径仍未穷尽。
- NCAB 的旧协议修复仍有效；本次不宣称某个公网 NCAB 实例支持 HTTPS。原生 Win10 与远端 Action 未实测。
